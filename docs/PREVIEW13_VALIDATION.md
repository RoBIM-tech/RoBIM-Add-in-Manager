# Preview 13 · 구형 시트 Add-in의 최초 Reload 전환 · 2026-10-20

`기존 외부 설치는 제거하지 않습니다` 메시지는 실제 사용자 ApplicationPlugins의 Sheets 0.1.0 직접 등록 번들과 Manager 관리 기록의 불일치에서 발생했다. 이 경우는 pyRevit 버튼 선택 오류와 구분한다. 구형 번들은 IExternalApplication.OnStartup으로 직접 리본을 생성하므로 최초 전환에는 Revit 종료가 필요하다.

구형 설치는 알려진 기존 배포 ZIP(SHA-256 D4D57E31B099476E7EEF203FC3A72EFEDF2BE0AA7879A1F5912F481D923F0852)의 206개 파일과 모두 일치했다. workspace 복구용 사본을 만들고 파일별 해시를 검증한 뒤, 사용자가 모델 저장 후 Revit을 종료했다.

변경:

- 기존 직접 설치를 미설치로 표시하지 않고 `기존 직접 설치 · 전환 필요`와 `전환하기` 버튼으로 안내한다.
- 알려진 구형 ZIP을 새 참조 폴더에 추출하고, 기존 설치의 모든 파일이 참조와 일치할 때만 명시적으로 관리 기록을 연결한다. 추가/변경 파일이 있거나 참조가 다르면 인계·제거를 차단한다. 일반 외부 설치를 자동으로 삭제하지 않는다.
- 전환 시 기존 관리 백업을 만든 뒤 직접 등록 번들을 해제하고 새 command-only 모듈을 준비한다. 준비 실패 시 이전 관리 백업을 복원한다. 인계 전/후 및 실제 제거 전 Revit 종료 상태와 설치 해시를 재검사한다.
- GUI와 내부 native-toggle 도구가 같은 전환 경로를 사용한다. Revit이 닫혀 있으면 준비 상태에 `Revit 시작 시 반영`을 표시한다. 고정 Native Host와 pyRevit core는 변경하지 않는다.

검증:

- Manager 회귀 113/113. 검증된 외부 설치의 무변경 인계/백업, 추가 사용자 파일 보존, 호스트 시작 경쟁 시 인계 차단, 자기 참조/다른 호스트 패키지 거부 포함.
- 실제 사용자 전환: 구형 직접 등록 번들은 관리 백업 후 ApplicationPlugins에서 해제됐다. Sheets 0.2.0-preview.1의 create-sheets 명령을 선택한 TargetPid=0 요청을 준비했다. 사용자의 모델은 수정하지 않았다.
- 후속 실제 Revit 확인: 모델 인수 없이 Revit 2026.5를 다시 실행해 Sheets 0.2.0-preview.1 버튼 1개의 `applied` 응답을 확인했다. 구형 직접 등록 폴더가 없고 관리 백업의 206개 파일이 전환 전 지문과 모두 일치함을 재검사했다. 시트 창을 열어 실제 프로젝트의 시트를 생성하는 작업은 실행하지 않았다. 이전의 probe 검증과 구분해 실제 Sheets 모듈 등록 성공을 기록한다.
- 예시 WinForms UI 61/61, Portable 임시 설치/재설치/제거/보존/패키지 검사 10항목 통과. 사용자 Manager Preview 13 설치 파일과 검증된 배포 실행 파일의 해시가 일치한다.

개인 경로·전체 설치 해시·복구 경로는 workspace의 로컬 migration-plan 및 배포 기록에 보관하며 Git에 포함하지 않는다.
