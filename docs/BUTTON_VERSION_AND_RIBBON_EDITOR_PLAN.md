# 버튼 버전 선택과 리본 편집 — 구현 계획

상태: 설계 단계. 아직 설치된 Preview 14에는 포함되지 않았다.

## 사용자 요청

- 기존 수동 RoBIM 설치를 백업 후 활성 경로에서 제거하고 Manager 관리 설치만 남긴다.
- 각 버튼에서 설치할 버전을 선택한다. 버튼별 개발 브랜치를 사용할 수 있다.
- Manager에 리본 편집 화면을 추가한다. 탭·패널 생성, 버튼 드래그앤드롭, 순서 및 크기 설정을 제공한다.

## 관리 구조

개발 브랜치는 저장소 내부 버튼별 작업 브랜치로 유지한다. 배포는 브랜치의 이동하는 HEAD가 아니라 검증된 커밋 SHA 또는 릴리스 태그와 ZIP SHA-256으로 고정한다. 새 브랜치를 임의로 만들거나 기존 브랜치를 변경하지 않는다.

버튼 카탈로그에는 영구 buttonId, host, moduleId, version, sourceRef, commit, artifact, sha256, 공용 라이브러리 의존 버전과 호스트 호환 범위를 저장한다. 한 DLL에 여러 명령이 있는 경우 버전 변경의 영향 범위를 표시한다. 호환되지 않는 버튼 버전 조합을 섞어 설치하지 않는다. 독립적으로 배포할 버튼은 명령 모듈을 분리해야 한다.

## 화면

카드의 더보기 메뉴에 버전 선택을 둔다. 현재 설치·적용 대기·설치 가능 버전을 구분하고 안정판과 개발 브랜치를 분리한다.

별도의 리본 편집 화면에는 호스트 선택, 설치된 버튼 목록, 탭/패널 트리 및 리본 미리보기, 선택 항목 속성(표시 이름·큰/작은 버튼·순서)을 둔다. 버튼은 목록에서 패널로 드래그하고 기존 항목도 재배치할 수 있다. 드래그가 어려운 경우 이동 메뉴와 키보드 대안을 제공한다.

설정 저장과 실제 적용은 구분한다. 저장 전 검증과 미리보기, 기본값 복원, 변경 취소, 내보내기/가져오기를 제공한다. 설치·제거 상태는 별도로 유지한다.

## 적용 규칙

레이아웃은 설치 원본과 분리한 사용자 설정으로 저장한다. 업데이트·버전 전환 후에도 영구 buttonId로 연결한다. 모르는 ID나 제거된 버튼은 설정을 삭제하지 않고 미설치 상태로 보존한다.

pyRevit, CAD, Native Revit 각각의 적용 어댑터가 필요하다. pyRevit core는 수정하지 않는다. 원본 버튼의 상대 경로·공용 라이브러리 참조를 검증하고 파일 이동만으로 레이아웃을 적용하지 않는다. Native Host의 기존 패널/버튼 제거와 큰/작은 그룹 재구성은 호스트 제약을 확인한 후 Reload 또는 재시작 필요로 명확히 표시한다.

## 완료 조건

- 실제 설치 상태와 선택된 버전의 소유권·해시 확인
- 의존성 충돌·동일 ID 중복·지원되지 않는 호스트 차단
- 드래그 이동·다중 탭/패널·크기 선택·취소·복원·설정 재열기 검증
- 각 호스트에서 적용 후 실제 표시와 명령 실행 확인
- 기존 도구 및 개인 로컬 수정본 복구 가능성 보존

## 현재 작업 상태

수동 pyRevit RoBIM 1,056개 파일 백업·해시 검증 완료. 선택 프로필 설치 후 pyRevit CLI가 Git 이외의 확장을 찾지 못하는 문제를 확인했고, 표준 INI 활성 플래그를 보존하여 변경하는 대체 경로를 추가했다. 엔진 검사 114/114 통과. 아직 설치본에는 배포하지 않았다.

기존 원본 제거 및 전환 완료는 Revit이 다시 실행되어 중단했다. 사용자의 재종료 응답 대기 중이다. Native Host는 파일이 실제 존재하지만 Revit 시작 로그에서는 WrongAssembly/파일 없음으로 보고되므로 추가 확인 및 복구가 필요하다. 해결 완료로 표시하지 않는다.
