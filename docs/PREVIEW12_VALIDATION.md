# Preview 12 · 기존 설치 인식과 버튼 제거 오류 수정 · 2026-10-20

보고된 증상은 Revit 실행 중 제거 버튼 비활성, 기존 버튼의 미설치 표시/설치 실패, CAD 버튼 제거 시 오류였다.

재현 및 수정:

- Preview 11의 처리 경로는 실행 중 준비를 지원했지만 카드 활성화 경로에 `!running` 조건이 남아 있었다. 해당 조건을 제거하고 안내를 `적용 및 Reload`로 맞췄다.
- 기존 pyRevit 경로는 Git/버전 조회 전에 설치 경로로 보존한다. Git 정보 확인 실패를 파일 미설치로 표시하지 않는다. 버튼 inventory는 Manager 소유 기록 대신 실제 설치 폴더와 활성 프로필을 기준으로 읽고, 다운로드한 기능 목록과 구분한다. INI의 core.userextensions 경로만 읽는 fallback과 설치된 pyrevit.exe의 명시적 경로 해석을 추가했다. pyRevit 원본/config는 수정하지 않는다.
- 실제 사용자 CAD 스냅샷을 사용하는 카드 검사에서 `Snapshots/<id>/RoBIM.Cad.Loader.dll` FileNotFoundException을 재현했다. 기능 스냅샷은 고정 로더를 포함하지 않으므로 request.LoaderHash와 실제 설치 로더를 비교하도록 수정했다. 제거와 재추가 모두 동일한 검증된 Source/Toggle 경로를 사용한다.
- 새 패키지를 다운로드했어도 기존 action의 선택 변경은 현재 설치된 기능 스냅샷을 우선 사용한다. 새 로더 버전이 기존 버튼의 제거까지 막지 않도록 했다. 실제 고정 로더 변경/로컬 수정은 계속 차단한다. 카드 상태 조회 오류는 해당 카드의 `설치 상태 확인 필요`로 표시한다.

검증 결과:

- Manager 회귀 109/109. Git 정보 조회 실패 후 기존 source 보존, 소유 기록 없는 설치 인식, 다운로드-only 구분, 설정 경로 읽기, 실제 스냅샷에 로더가 없는 경우의 제거/재추가, 새 다운로드 로더와 기존 선택 변경 분리, 고정 로더 변경 차단 포함.
- 배포 EXE 예시 WinForms 검사 61/61.
- 동일 배포 EXE의 실제 설치 카드 검사: Revit/AutoCAD 실행 중 pyRevit 35개 모두 설치됨/제거 활성, CAD 5개 중 제거 활성 4개·설치 활성 1개. 예시 데이터가 아닌 현재 설치와 준비/적용 상태를 읽었다.
- 실제 설치 payload의 임시 사본 통합 검사 7/7: pyRevit 35→34→35, CAD 4→3→4. 사용자의 설치 파일·원본·설치 기록·CAD pending 요청이 변하지 않았음을 비교했다. 사용자 모델이나 실제 프로필/선택에는 제거를 적용하지 않았다.

실제 pyRevit/AutoCAD 리본의 최종 반영은 사용자가 선택한 버튼 변경을 각 호스트의 Reload로 적용할 때 확인한다. 이번 임시 사본 검증을 실제 사용자 버튼을 제거했다는 의미로 표현하지 않는다.

진단용 `--inspect-installed-card-ui <json>`은 현재 설치를 읽어 카드 상태/활성 여부를 기록하며 설치·제거 명령을 실행하지 않는다. `Manager.Tests --check-existing-button-workflows <new-directory>`는 실제 설치를 읽어 새로운 임시 폴더에서만 선택 변경을 수행한다. 개인 경로와 설치 상태 출력은 Git에 포함하지 않는다.

배포: Portable 임시 설치/재설치/제거/보존/패키지 검사 10/10. 사용자 설치 Preview 12로 업데이트 후 배포 EXE와 해시 일치. 설치된 EXE에서도 기존 pyRevit 35개 제거 활성/CAD 제거 4개·설치 1개 활성을 확인했다. Revit/AutoCAD 세션과 사용자 선택을 유지하고 Manager만 다시 열었다. 이전 설치/변경 소스 백업은 로컬 배포 기록에 보관한다.
