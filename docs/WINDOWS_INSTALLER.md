# Windows 설치 프로그램 변경 — Preview 6

기존 Setup은 .NET 부트스트랩에서 PowerShell 복사·레지스트리 등록을 호출했다. 새 Setup은 Inno Setup 6.4.3의 파일 설치·롤백·바로가기·앱 등록·전용 unins000.exe를 사용한다. 기존 물리 설치 경로는 유지한다.

- 사용자별 설치, 관리자 권한 요청 없음. 매니저만 설치하며 CAD/Revit 도구나 모델은 변경하지 않는다.
- Guard.ps1은 경로의 링크, 기존 설치 소유권, 매니저 실행 여부를 검사한다. 소유권이 없는 비어 있지 않은 폴더에는 설치하지 않는다.
- 기존 JSON 기록에서 새 INI 설치 기록으로 이행한다. 기존 앱 등록은 설치 경로가 일치할 때만 정리한다.
- preview.44부터 제거 확인 후 관리 도구·Host 등록·검색 기록·캐시·백업을 오프라인 정리하고 Manager 실행 파일을 제거한다. 개인 설정은 삭제/유지를 선택한다. 외부 도구·알 수 없는 프로그램 폴더 파일·공용 GitHub 인증은 보존한다. 아래 Preview 6 결과는 당시 구현의 역사 기록이다. [현재 제거 구현과 검증](developer/UNINSTALL.md)
- Portable Install.ps1/Uninstall.ps1은 Setup 설치 기록이 있으면 중단해 두 설치 방식의 혼용을 막는다.
- 과거 RoBIM.Setup 프로젝트는 제거했으며 Setup 빌드는 installer/Manager.iss가 담당한다.

빌드 도구는 공식 GitHub 배포의 고정 SHA-256 F3C42116542C4CC57263C5BA6C4FEABFC49FE771F2F98A79D2F7628B8762723B 및 Windows 서명을 확인한다. 6.4.3의 동봉 License.txt는 상업적 사용을 허용하며, 이후 버전으로 임의 업그레이드하지 않는다.

## 확인 결과 (2026-10-15)

임시 경로의 네이티브 Setup에서 설치, 앱 등록과 전용 삭제 명령, 재설치, 제거, 알 수 없는 파일 보존, 관리되지 않는 폴더 거부를 확인했다. 테스트 설치본은 독립 AppId와 별도 폴더를 사용하고 바탕화면/시작 메뉴 바로가기를 만들지 않는다. Portable 설치·재설치·제거와 실제 EXE 렌더 검증도 통과했다.

현재 사용자 설치를 Preview 6으로 업데이트했다. 실행 중이던 Windows 설정 프로세스에는 이전 목록이 남아 있었다. 해당 설정 프로세스를 새로 열었을 때 설치된 앱에 RoBIM Add-in Manager / 1.0.0-preview.6 / 52.8MB가 표시되는 것과 ⋯ 메뉴의 제거 항목을 실제 화면에서 확인했다. 현재 PC의 매니저를 제거하는 작업은 하지 않았다. 제어판의 기존 Explorer 창은 목록을 유지했으므로 해당 창의 표시까지 검증했다고 간주하지 않는다.

기존 Preview 5의 누락 원인은 확정하지 않았다. 레지스트리 값 존재만으로 앱 목록 표시를 검증했다는 과거 안내는 충분하지 않았다. 이번 버전에서는 실제 Windows 설정 화면과 전용 제거 프로그램의 임시 설치 테스트를 구분해 확인했다.

아이콘은 남색/흰색/민트색 R 벡터 원본과 16~256px의 9개 프레임을 가진 ICO를 포함한다. EXE 리소스, 프로그램 창, Setup, 앱 목록, 바로가기에 연결했다. assets/build-icon.ps1로 SVG와 같은 도형을 재생성할 수 있다. 샌드박스 내 Portable 화면 렌더는 한 번 15초 제한에 걸렸으며, 실제 사용자 환경에서 같은 검증을 다시 실행해 통과했다.
