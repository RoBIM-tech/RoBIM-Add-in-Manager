## 설치 EXE: 8개 확인

- Setup EXE의 내장 페이로드 해제
- Windows PowerShell 5.1에서 임시 경로 설치
- 동일 경로 재설치
- 설치된 런타임 포함 EXE의 화면 렌더링
- 제거 스크립트 실행
- 관리자가 만들지 않은 파일 보존
- 관리 대상이 아닌 기존 설치 폴더 덮어쓰기 거부
- 동봉 Reload 연결 ZIP 해시와 스크립트·YAML·밝은/어두운 아이콘 존재 확인

관리자 UI는 WinForms 실제 컨트롤을 렌더링해 한글·목록·버튼 배치를 확인했습니다. 렌더 미리보기의 설치 버전은 화면 검증용 예시입니다.

현재 사용자 계정에 Preview 3를 설치하고 설치 EXE 해시를 확인했습니다. 별도 Reload 확장도 설치했습니다. 실행 중이던 Preview 2의 숨겨진 창 복원, 정상 종료를 통한 업데이트, Preview 3의 두 번째 실행이 종료되고 기존 창이 유지되는 것을 확인했습니다. Revit은 동일 PID로 유지했습니다. 연결 스크립트는 설치된 pyRevit IronPython 3.4 엔진으로 문법 컴파일했으며 Revit 안에서 실행하지 않았습니다.

Preview 4로 현재 매니저를 업데이트하고 바이너리 해시를 확인했습니다. 확장 패키지·계정 화면은 배포 EXE로 렌더링했습니다. 실제 PAT는 제공받지 않았으므로 유효 PAT를 새로 저장하는 대화형 흐름은 미검증이며, 기존 브라우저 인증의 실제 사용자 조회와 임시 자격 증명 저장·조회·삭제, 잘못된 PAT 거부를 구분하여 검증했습니다. 토큰이나 기존 GitHub 인증은 테스트에서 교체하지 않았습니다. 두 RoBIM 저장소에 자동 검색용 토픽을 추가했으며 Revit 저장소 소스는 수정하지 않았습니다.

## 남은 확인

- 사용자가 관리자에서 도구를 선택해 설치하고 AutoCAD/Revit을 재시작하는 전체 대화형 흐름
- 신규 브라우저 로그인과 실제 pyRevit 프로필 적용. 테스트는 기존 인증을 재사용하고 현재 활성 프로필을 변경하지 않음
- AutoCAD 리본 버튼은 기존 CAD 애드인에 없으며 `DHNET` 명령으로 실행
- Revit 탭과 각 명령의 실제 모델 동작은 기존 Revit 도구의 별도 검증 범위
- 서명되지 않은 미리보기 설치 프로그램이며 조직의 배포·보안 정책에 따른 배포 검토는 별도
- 커스텀 AutoCAD 설치 경로, 독립 Revit `.addin` 패키지, 백그라운드 업데이트 예약은 지원하지 않음
