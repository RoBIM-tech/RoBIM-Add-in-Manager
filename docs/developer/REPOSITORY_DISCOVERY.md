# 저장소 검색과 제작자·조직 설정

Preview 37부터 명시적 새로고침은 검색 대상의 새 저장소 발견과 기존 정식/TEST 업데이트 확인을 함께 수행합니다. 시작·탭 전환은 로컬 저장 목록을 사용합니다. 검색 자체는 ZIP 다운로드·설치·리본/모델 변경을 수행하지 않습니다.

RepositoryDiscovery가 repository-publishers.json의 여러 개인/조직과 연결 계정 범위를 읽습니다. 인증된 user/repos로 접근 가능한 비공개 범위를 확보하고 선택한 소유자로 필터링하며, 개인/조직의 저장소 목록도 보완 조회합니다. robim-addon 토픽과 기본 브랜치의 유효한 robim-package.json을 확인합니다. 기반 저장소의 빈 packages는 설치 도구로 취급하지 않습니다.

발견 결과는 discovered-repositories.json에 원자적으로 저장하고 동봉 기본 목록·사용자 URL 등록과 합칩니다. 저장소 주소로 중복을 제거하고 네이티브 패키지·모듈 ID/설치 폴더 충돌은 차단합니다. 기본 브랜치/pushed_at이 같으면 표시 파일 재조회를 줄입니다. 접근 실패·검색 대상 중지/삭제 때문에 기존 발견·설치 항목을 제거하지 않습니다.

신규 표시 정보는 moduleId/commandId를 함께 제공하며 SingleNativeButton에서 ZIP의 실제 ID와 대조합니다. 동봉 등록이 없는 첫 카드도 바로 설치할 수 있습니다. 구형 표시 정보는 단일 명령 ZIP과 기존 캐시를 검증하는 호환 경로를 사용합니다. 설치 직전 다른 저장소가 사용 중인 모듈 ID와 충돌하는지도 확인합니다. 중앙 catalog는 기본 추천/저장소 이전의 호환성에 사용하며 새 도구마다 Manager를 다시 배포하는 조건이 아닙니다.

검사: Manager.Tests의 검색 대상 설정·개인/조직/비공개 범위·변경 없는 캐시·권한 실패·ID/폴더 충돌·기반 저장소·대상 삭제, 실제 WinForms 설정 추가/삭제/중지/저장 경로를 검사합니다. 일반 Windows GitHub 조회에서도 CentralClone을 중앙 동봉 없이 새 TEST 카드로 발견했고 설치 선택이 유지됨을 확인했습니다. 실제 버튼 기능 실행이나 모델 쓰기 검증은 별도입니다.
